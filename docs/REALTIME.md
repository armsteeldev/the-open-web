# Realtime protocol

`GET /api/events?space=wall` upgrades a same-origin WebSocket. A connection subscribes to exactly one currently registered space for its lifetime; unregistered, missing or repeated space parameters are closed with policy code 1008. Client messages are not accepted. Server messages are JSON `{v:1,space:"wall",type:"pixel",x,y,color}` and are delivered only to sockets subscribed to that space. The endpoint now requires `space`; an older frontend without it cannot connect. Release frontend and backend together.

The initial snapshot is read from `GET /api/wall/tile/:x/:y` as 10,000 row-major palette indices; clients refetch visible tiles on reconnect. Reconnection uses exponential backoff with jitter, capped at 30 seconds. Failed tile requests are retried after a short delay. A placement is `POST /api/wall/pixel` with JSON `{x,y,color}` and a session cookie. Success returns `{ok:true,retryAt,retryAfterMs}` after commit; 429 can include `retryAt` and `retryAfterMs`. `retryAt` is milliseconds since epoch, while `retryAfterMs` is the remaining wait when the response is created. A heartbeat removes dead connections; connection, payload and buffered-data limits bound resources.

There is no durable event replay. A future space must define its own snapshot and race-free reconciliation after reconnect; add its registered space ID and publish events to that channel. Tests use a second synthetic channel but no unfinished space is exposed to visitors.
