# Database

SQLite uses WAL and a 5-second busy timeout. Numbered migrations in `database/migrations` are applied in order, each in a transaction, and recorded in `migrations`. Versions must be consecutive starting at 001; a database with a newer or inconsistent history fails closed. Migration files are immutable once released. Back up before upgrading; the runner does not reverse migrations. `wall_tiles` holds one 10,000-byte palette-index blob per touched 100 × 100 tile, keyed by tile coordinates. Tile length and palette indices are validated before reads and writes; invalid data fails closed. `visitor_cooldowns` stores a SHA-256 digest of the random cookie and the latest placement timestamp. Migration 002 indexes timestamps so expired digests can be removed. The server purges at most 500 expired rows every 30 seconds and during placements; a large backlog is cleared over subsequent batches. Neither table stores IP addresses. `BEGIN IMMEDIATE` wraps expiry cleanup, cooldown check, tile overwrite and timestamp update; errors roll back. There is no automatic wall reset. See BACKUPS.md before moving a database.
