# Operations

`GET /api/health` checks that the process can read migration metadata and runs SQLite `quick_check(1)` at most once every 30 seconds; metadata is checked on each request. It does not verify writeability or public routing. Use `systemctl status the-open-web`, `journalctl -u the-open-web`, and an HTTPS request through Caddy after installation. The service writes logs to journald, not per-application files; host journal retention and rotation settings govern storage. Application request logging is disabled and Caddy access logging is not enabled in the site template; review privacy and retention before enabling it. For an immediate write stop, preconfigure `WRITE_GATE_PATH` as an absolute path in an operator-controlled directory readable by the service. Creating a file at that path blocks public writes on the next request without a restart; removing that specific flag re-enables writes. A missing or unreadable parent directory fails closed. Do not make the directory writable by untrusted users. Alternatively set `WRITES_ENABLED=false` and restart only this service. Re-enable only after resolving the incident. Do not expose the loopback port publicly. Per address, broad guards cap requests at 600 per minute and session/write requests at 180 per minute. Successful placements also share a token bucket with a 12-placement burst and one token refilling per second (up to 72 placements in a 60-second span); this bounds cookie rotation while allowing several visitors behind one address. The placement budget resets on restart and cannot prevent distributed abuse. All IP-based limits rely on correct trusted-proxy configuration. Network addresses are held in bounded, periodically cleaned memory, not persisted. Cooldown identity digests are deleted in bounded batches when expired. Review security and abuse handling before public exposure.

Configuration: `PORT` (default 4322), `DB_PATH` (default `./data/open-web.sqlite`; parent must exist), `ORIGIN` (exact browser origin, default `http://localhost:4321`), `WRITES_ENABLED` (`false` disables), `COOKIE_SECURE` (`true` in production), and optional `WRITE_GATE_PATH` (absolute path; presence blocks writes). The placement cooldown is fixed at 10,000 ms; a conflicting `COOLDOWN_MS` value prevents startup. Invalid ports, booleans and origins prevent startup; HTTPS requires `COOKIE_SECURE=true`. SIGTERM and SIGINT close connections and the database before exit. Environment changes require restart; creating or removing the configured gate file does not. Caddy has its own access logging policy; do not enable verbose request logs without a retention/privacy decision.
